# solver

职责：差分约束可行性、偏移上下界、连通分量与可复核负环见证。

## 当前能力

已实现全图可行性判定、一组可行偏移和一个可复核的负环证据。偏移区间与分量分别求解属于下一阶段；本阶段只返回整份约束图的结论。

### 入口

- `solve(input : ConstraintSet, limits?) -> SolveReport raise SolveError`：保留完整约束构建报告，包含原始消息、来源、容差、先验及未解决关联组。
- `solve_constraints(constraints, clock_ids?=[], limits?) -> ConstraintSolution raise SolveError`：直接分析已验证的基础约束。`clock_ids` 用于保留孤立时钟，约束两端的时钟会自动加入；显式列表长度也受时钟数量上限限制，重复名称不增加图中的时钟数。

结果中的原始约束顺序保持不变，时钟按名称排序。直接入口的遍历与见证选择受输入边顺序影响；固定输入产生稳定结果，不承诺任意重排后的见证完全相同。

### 可行结果

`Feasible(offsets~)` 为每个时钟返回一个 Int64 微秒偏移。Bellman–Ford 的距离初始为零，相当于连接所有时钟的零权超级源；因此所有返回偏移不大于零，没有选定任何真实机器作为参考时钟。

返回前逐条检查 `offset(left) <= offset(right) + upper_bound`。这是同一组可行偏移，不是偏移区间、唯一校准结果或 UTC 时间。没有约束的时钟得到零偏移，表示一种自由坐标选择。空图可行但没有证据覆盖；未解决消息仍需查看原始关联报告。

### 冲突结果

`Infeasible(cycle~)` 包含一个沿图边正向排列的闭环及其严格为负的边权总和。`CycleEdge.constraint_index` 是原始约束数组的零基索引：

```text
report.input.constraints[index].evidence
```

可用于回查完整消息对或先验。直接入口则用 `solution.constraints[index]` 回查基础约束及来源 ID。负环起点规范化为环中原始约束索引最小的边；这只是稳定的展示规则，不保证最小冲突集合。

负权自环可直接作为冲突见证。其他负环在第 V 轮仍有松弛时沿前驱链提取；返回前检查边连接、闭合及权重和。权重求和优先交替正负项，避免最终值可表示时因求和顺序引入溢出。

## 资源与算术边界

`SolveLimits::new` 默认限制为 256 个时钟、20,000 条约束和 5,000,000 次边访问；可配置硬上限分别为 4,096、2,000,000 和 1,000,000,000。参数必须为正，零边图仍可分析。

边访问预算覆盖松弛、前驱遍历、可行解核对、负环核对与权重求和，不包含图索引和排序。无边图不消耗边访问预算。单轮复杂度 O(E)，最多 V 轮；结果核对和见证提取也消耗预算。

所有路径加法和环权求和检查 Int64 溢出。松弛路径可能超出 Int64，即使数学上存在可行偏移，也可能返回 `ArithmeticOverflow`；本阶段不使用任意精度运算或重定位坐标来继续分析。环权总和超出 Int64 时同样报错，不能据此推断图可行或冲突。

`SolveError` 区分配置错误、时钟／约束超限、边访问预算耗尽、算术溢出和内部见证核对失败。失败不返回部分解或可行性结论。
