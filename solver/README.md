# solver

职责：差分约束可行性、偏移上下界、连通分量与可复核负环见证。

## 当前能力

已实现全图可行性判定、一组可行偏移、可复核负环证据，以及按弱连通分量独立进行的参考时钟选择和偏移区间分析。原有 solve 入口保留整图分析行为；新增 analyze 入口用于分量和区间。

### 入口

- `solve(input : ConstraintSet, limits?) -> SolveReport raise SolveError`：保留完整约束构建报告，包含原始消息、来源、容差、先验及未解决关联组。
- `solve_constraints(constraints, clock_ids?=[], limits?) -> ConstraintSolution raise SolveError`：直接分析已验证的基础约束。`clock_ids` 用于保留孤立时钟，约束两端的时钟会自动加入；显式列表长度也受时钟数量上限限制，重复名称不增加图中的时钟数。

结果中的原始约束顺序保持不变，时钟按名称排序。直接入口的遍历与见证选择受输入边顺序影响；固定输入产生稳定结果，不承诺任意重排后的见证完全相同。

### 可行结果

`Feasible(offsets~)` 为每个时钟返回一个 Int64 微秒偏移。Bellman–Ford 的距离初始为零，相当于连接所有时钟的零权超级源；因此所有返回偏移不大于零，没有选定任何真实机器作为参考时钟。

返回前逐条检查 `offset(left) <= offset(right) + upper_bound`。这是同一组可行偏移，不是偏移区间、唯一校准结果或 UTC 时间。没有约束的时钟得到零偏移，表示一种自由坐标选择。空图可行但没有证据覆盖；未解决消息仍需查看原始关联报告。

### 冲突结果

`Infeasible(cycle~)` 包含一个沿图边正向排列的闭环及其严格为负的边权总和。`CycleEdge.constraint_index` 是原始约束数组的零基索引：

```text
report.input.constraints[index].evidence
```

可用于回查完整消息对或先验。直接入口则用 `solution.constraints[index]` 回查基础约束及来源 ID。负环起点规范化为环中原始约束索引最小的边；这只是稳定的展示规则，不保证最小冲突集合。

负权自环可直接作为冲突见证。其他负环在第 V 轮仍有松弛时沿前驱链提取；返回前检查边连接、闭合及权重和。权重求和优先交替正负项，避免最终值可表示时因求和顺序引入溢出。

## 资源与算术边界

`SolveLimits::new` 默认限制为 256 个时钟、20,000 条约束和 5,000,000 次边访问；可配置硬上限分别为 4,096、2,000,000 和 1,000,000,000。参数必须为正，零边图仍可分析。

边访问预算覆盖松弛、前驱遍历、可行解核对、负环核对与权重求和，不包含图索引和排序。analyze 还将分量划分中的两次边扫描、参考坐标核对和上下界路径扫描计入同一全局预算。无边图不消耗边访问预算。可行性单轮复杂度 O(E)，最多 V 轮；每个方向的区间最短路最多 V-1 轮。

所有路径加法和环权求和检查 Int64 溢出。松弛路径可能超出 Int64，即使数学上存在可行偏移，也可能返回 `ArithmeticOverflow`；本阶段不使用任意精度运算或重定位坐标来继续分析。环权总和超出 Int64 时同样报错，不能据此推断图可行或冲突。

`SolveError` 区分配置错误、时钟／约束超限、边访问预算耗尽、算术溢出和内部见证核对失败。solve 失败不返回部分解或可行性结论；analyze 的分量计算失败明确记录为 ComponentFailed，语义见下文。

## 分量与偏移区间

### 新入口

- `analyze(input, reference_clock?, limits?) -> AnalysisReport raise SolveError` 保留完整构建报告，结果位于 analysis 字段。
- `analyze_constraints(constraints, clock_ids?=[], reference_clock?, limits?) -> ConstraintAnalysis raise SolveError` 直接分析基础约束。

若指定参考时钟，必须已经存在于输入图中；只在其所属分量中使用它。其他分量默认使用名称字典序最小的时钟。默认情况下所有分量均采用各自最小名称。分量按最小名称排序，component_id 从零递增，分量内时钟也按名称排序。这里明确使用 UTF-16 码元字典序，不使用 MoonBit String.compare 的长度优先顺序；输入关联和原始约束仍保持各自既定顺序。空图返回空分量集合；向空图指定不存在的参考时钟会报错。

### 三种分量结果

| 结果 | 内容与含义 |
| --- | --- |
| ComponentFeasible | 同一组参考归零的可行偏移，以及每个时钟的边际上下界 |
| ComponentInfeasible | 这个分量内的一个负环，仍使用原始全局约束索引 |
| ComponentFailed | 这个分量未完成分析，携带预算、溢出或内部核对错误；不作可行性结论 |

输入／配置错误、未知参考时钟，以及划分分量之前或期间耗尽预算，会使整个入口报错。进入逐分量求解后，算术失败只影响当前分量，其他分量继续使用剩余预算；预算耗尽后剩余分量均记为失败。返回 ConstraintAnalysis 不意味着所有分量都分析成功，调用者必须检查每个 outcome。

每个分量的统计只包含自身求解、区间计算及核对；总统计还包含分量划分的边访问。因此各分量 edge_visits 之和可能小于总数。passes 记录完成的可行性和最短路扫描轮数。

### 数学约定

在一个可行分量内，参考时钟 r 的偏移设为零：

```text
upper(o_i) = d(r, i)
lower(o_i) = -d(i, r)
```

原图从 r 出发计算上界；反向图保留原权重，从 r 出发计算下界所需的路径。没有对应方向的路径时返回 Unbounded；存在有限路径时返回 Finite(Int64)。Unbounded 表示数学上的无界，不用来代替溢出或未完成分析。

参考时钟自身区间为 [0,0]。孤立时钟也是自己的参考，[0,0] 只表示自身坐标，不能说明它相对于其他分量的真实偏移。

代表偏移取自同一组可行解，统一减去参考偏移，并再次核对全部分量原始约束及其所属区间。各时钟的区间端点分别可达，不保证不同端点能够同时取得；不能拼接端点来绘制时间线。不同分量没有共同时间基准，不推断其间的确定先后。

路径运算、参考坐标平移或有限下界取反超出 Int64 时，分量返回显式失败；不会改成 Unbounded。即使存在其他可表示的代表解，当前实现也不会重新搜索来规避坐标平移溢出。约束核对使用不溢出的数学比较，避免右侧加法越界造成误判。
